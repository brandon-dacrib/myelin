Bridges: the server deploys them itself. Enable one under Bridges in the admin interface and
the bridge operator ({{ include "hs.fullname" . }}-bridges-operator) runs each person's bridge
as its own pod in this namespace:
  kubectl -n {{ .Release.Namespace }} get bridges

Locked out? When nobody can sign in as an administrator, run this where the server keeps its
signing key -- the pod -- and open the link it prints:
  kubectl -n {{ .Release.Namespace }} exec {{ include "hs.fullname" . }}-0 -- hs recover
It resets an administrator's password and signs you in. The link works once and expires in
fifteen minutes; only whoever can run a command in the pod, and so read the server's signing
key, can get one. If the server has no administrator at all, it prints the setup link instead.
{{- if not .Values.secrets.signingKey.existingSecret }}

Signing key: generated on the first start into keys/ on the data volume, and read back on every
restart. The volume is kept on `helm uninstall` (storage.embedded.resourcePolicy), so a reinstall
keeps the key too. To bring your own instead, or before moving to cluster mode:
  hs generate-signing-key -o signing.key
  kubectl -n {{ .Release.Namespace }} create secret generic my-hs-signing-key --from-file=signing.key
  helm upgrade ... --set secrets.signingKey.existingSecret=my-hs-signing-key
{{- end }}
