# 0003. Management web interface stack

Date: 2026-09-18. Status: accepted. Track: 16.

## Decision

`web/` is a TypeScript single-page application:

- **Build**: Vite 8, `@vitejs/plugin-react` (Babel-based fast refresh).
- **UI**: React 19, Radix primitives via the `radix-ui` umbrella package (unstyled, accessible), `class-variance-authority` + `clsx` + `tailwind-merge` for variant styling, `lucide-react` for icons.
- **Styling**: Tailwind CSS 4 (CSS-first configuration; no `tailwind.config.js`). Design tokens live as CSS custom properties in `web/src/styles/tokens.css`, mapped into Tailwind's `@theme` so both raw CSS and utility classes read the same source of truth. Light and dark themes are two token blocks selected by `[data-theme]` plus `prefers-color-scheme`.
- **Data**: TanStack Query 5 for server state and caching; a hand-written thin fetch wrapper (`src/api/client.ts`) built on `openapi-fetch`, typed against a generated schema (`src/api/schema.d.ts`). The schema is generated by `scripts/generate-client.mjs` from, in priority order, `crates/hs-admin/openapi/openapi.yaml` (track 15's document, once it exists and is marked usable in its status file) or `web/mocks/openapi.yaml` (this track's own draft, used until then). The generated file is committed so `tsc -b` does not depend on a generation step running first; `npm run generate:client` refreshes it and is part of `npm run build`.
- **Routing**: TanStack Router 1, used with its code-based API (`createRootRoute`/`createRoute`/`createRouter` in `src/routes.tsx`) rather than file-based generation. Chosen for determinism while iterating quickly on an unstable route tree; the `@tanstack/router-plugin` devDependency is left installed but unused so a later switch to file-based routing is a config change, not a rewrite. Filters, sort, tab, selected row and pagination cursor live in the URL per `information-architecture.md` section 6.
- **Auth**: `oauth4webapi` against 07's OAuth issuer, authorization code + PKCE, admin scopes. Mocked in development by MSW-issued tokens until 07's issuer exists.
- **Mocking**: MSW 2 (`public/mockServiceWorker.js` already present) intercepts network requests in development (`npm run dev:mock`) and in Vitest/Playwright. Fixtures live in `src/mocks/data/`, handlers in `src/mocks/handlers.ts`, generated from the same `web/mocks/openapi.yaml` shapes as the typed client so mock and type drift is caught by `tsc`.
- **Testing**: Vitest 5 + Testing Library for unit and component tests (jsdom environment); Storybook 10 (`@storybook/react-vite`, `@storybook/addon-a11y`) for every primitive component, with axe checks built into the addon; Playwright 1 (`@axe-core/playwright`) for end-to-end flows, one spec per `flows.md` flow, axe-checked at every step.
- **Lint/format**: ESLint 9 flat config (`typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `eslint-plugin-jsx-a11y` in `strict`), Prettier 3.
- **Embedding**: production build output `web/dist/` (plain `index.html` + hashed assets, no SSR), embedded by track 15 via `rust-embed` and served at `/admin/`, per `docs/design/information-architecture.md` section 9.1 and `docs/rfcs/0016-admin-web-embedding.md` (to be written when 15's embedding hook exists). The same build also reads an optional `config.json` beside `index.html` for API base URL and issuer, so it can run as a standalone deployment.

## Why

This matches the brief's recommended stack (`docs/workstreams/16-management-web-interface.md`, "day-one work") and was already reflected in the `package.json` left by the interrupted attempt; this decision records it formally and fixes the two points the brief left open (routing style, schema generation source order).

## Consequences

- `npm run typecheck` never needs network or a running mock server; the committed schema file is regenerated by hand or by `npm run generate:client` when the source OpenAPI document changes.
- Until track 15 publishes an OpenAPI document its status file marks usable, this track's own `web/mocks/openapi.yaml` is authoritative for the mock server and the generated types. Divergences found when reconciling are recorded in `docs/status/16-management-web-interface.md` under "Decisions made", not silently absorbed.
- No server-side rendering; the interface is a static bundle plus client-side data fetching, consistent with "served by the homeserver, no SSR" in `information-architecture.md`.
